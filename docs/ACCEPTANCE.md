# 验收实录：让插件自己跑一个项目

这份记录不是「功能说明」，是**证据链**。它记的是：把 dsh-capability-router 装进真实会话后，让一个 agent 拿着它从「用户说一句话」走到「审查专家收口」，中间到底发生了什么、插件在哪里拖了后腿、改了什么。

之所以值得单独写：插件自身的单测（100 个场景）证明的是「代码按设计工作」，而这轮验收证明的是「设计在协作里站不站得住」。后者抓到的问题，没有一个是单测想得到的。

---

## 一、场景设定

| 项 | 内容 |
|---|---|
| 项目 | 家庭四路视频监控（Frigate + go2rtc 自托管，Tailscale 回连，本地录像 7 天） |
| 用户输入 | 一句话：「我想做个视频监控系统，家里四路摄像头，手机能实时看，从零开始。」 |
| 工作目录 | `_acceptance-video-surveillance`（无用户参与）、`_acceptance-video-surveillance-2`（带真人参与） |
| 参与会话 | 6 个：接单 2 个、实现 1 个、审查 2 个、记录 1 个 |

两个目录是刻意的：第一轮**禁止提问**（看它能不能在不打扰人的情况下自己兜住），第二轮**允许提问**（看它问得对不对）。

---

## 二、六轮流水

### 第 1 轮 · 接单（禁止提问）

调用序列：`expert("intake")` → `skill("doc-coauthoring")` → 写文件 → `expert("backend", {phase:"build"})`

产物：`REQUIREMENTS.md` 140 行、`TASKS.md` 161 行（8 张卡，每卡六项，含并行图与关键路径 T1→T2→T4→T8）。它自己反推了容量：1080p@2Mbps → 21.6GB/天/路 → 4 路 14 天 ≈ 1.21TB，据此选 4TB 盘——这不在任何模板里。

### 第 2 轮 · 接单（带真人提问）

只问 3 个，每个都带推荐答案与理由，还标了各自的阻塞范围：

| 问题 | 推荐 | 它给的理由（原文要点） |
|---|---|---|
| 组装 / 现成 NVR / 自研 | 开源自托管（Frigate + go2rtc） | 「家庭规模的难点是拉流稳定、编码兼容、移动端播放器，这三块成熟件已经磨了几年」 |
| 摄像头与网络现状 | 4 台 RTSP + PoE + x86 常开主机 | 「只支持厂商云的私有协议是第三天才会发现、代价最大的一类意外」 |
| 外网通道 + 录像策略 | Tailscale + 本地 7 天 | 「端口映射等于把内网门牌号贴门上」，并说明这决定验收标准的措辞 |

用户三个都选推荐项。落盘：`REQUIREMENTS.md` 86 行（A1–A12 每条带判定命令）、`TASKS.md` 95 行（T1–T7 + 并行图 + 关键路径）。

**结论**：提问协议成立——≤3 个、带推荐、带阻塞关系、并自带「不回就按假设写」的兜底。

### 第 3 轮 · 实现（T1 网络与存储底座）

边界：不 pull、不 up、不改系统。产出 14 个文件（compose、配置模板、渲染脚本、自检脚本、fstab/mkdirs、文档、证据）。

自检：`validate.sh` 17 项全 PASS，`docker compose config` 三种组合通过。它自己标了 **15 条「无法在本机验证」**（真实拉流、PoE、断电自启、7 天淘汰、手机首帧…）。

### 第 4 轮 · 审查（按 A1–A12 收口）

结论：**0 通过 / 1 不通过 / 11 无法判定**，定档「修完再交」。四个阻塞项：

| 项 | 内容 |
|---|---|
| **B1【P0】** | 裸 `ffmpeg:` 渲染成 `null`；Frigate 0.15.1 的 `ffmpeg` 非 Optional → 容器启动即退出。而 `validate.sh` 只做 `yaml.safe_load`，看不出来 |
| **B2【P0】** | go2rtc 流名 `cam1_main`，Frigate `live.stream_name` 默认取摄像头名 `cam1` → 手机实时画面静默失效（该函数只 `return` 不 `raise`） |
| **B3【P1】** | 4 处 `retain.mode: motion` → 语义上排除连续录像，A5「24h 缺口 <5min」配置层注定不成立 |
| **B4【P1】** | 口令原样替换、不做百分号编码，含 `@`/`:` 时静默生成坏 RTSP URL |

同时点名了 4 处**过度声明**，其中一处事实正好反了（「Frigate 对未知键是告警」——实际 `extra="forbid"`，启动即失败）。

### 第 5 轮 · 修复

用户拍板：A5 保留（不做降低标准的妥协）。于是 `mode: all`、容量按 605GB 重算、D4/U3 关闭。

`validate.sh` 17 → **28 项，全 PASS**；新增 `check-rendered-config.py`（ffmpeg 非空 + 无 null + 键名合法 + 不许写死 preset-vaapi）。

**最关键的一步是「门禁自证」**：把渲染产物写坏（ffmpeg=null、流名不存在、retain.mode=motion），门禁必须变红——实测 exit 1。没有这一条，28 项全绿仍然可能只是自我安慰。

### 第 6 轮 · 复核

另一个会话的审查专家重跑，不采信文档：

- 拉 Frigate v0.15.1 源码核对「非 Optional」「`extra="forbid"`」，逐字段比对默认值
- 自造更难的口令 `p@ss:w/rd#1%x&y?z=+ 中文` + 账号 `op@site`，node `new URL()` 与 python `urlsplit` 双解析还原全等
- **伪造一个「恒绿门禁」**，确认 3d 判据能识破
- 反例全在 `mktemp`，项目目录零污染

判定：B1–B4 已修（静态层），上轮阻塞项清零；整卡仍是「静态可交、A1–A12 动态待验」，并明确 **28 项 PASS 不为任何 A# 背书**。

## 三、插件暴露的问题与修法

这一节是这份记录的核心。每个问题都是真机上撞出来的，都对应一次版本改动。

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 交了卷（推进到 build）却返回「需求还没确认，先别开工」 | 闸门提示用推进**之前**的状态计算 | v0.16.1：按推进后状态判 |
| 2 | 新会话接手同一项目，阶段从 idle 起步，接管时被「不能跳着走」拒掉 | 阶段推进只许一格，但跨会话必然跨格 | v0.16.2：只禁后退，允许跨格 |
| 3 | 它报告「已推到 review」，状态其实还是 idle | 它没读工具返回值；拒绝信息混在正文里像普通提示 | v0.16.2：拒绝一律带 `⚠️ 阶段没有推进：` 前缀 |
| 4 | 同一个项目在三个会话里分别是 `spec` / `idle` / `review` | 阶段绑会话；而多代理协作必然换会话 | v0.17.0：阶段改为**项目级**（`<项目>/.capability-router/state.json`），会话只留指针 |
| 5 | 已在 review 时再交卷，收到「阶段没有推进」的告警 | 推进不幂等，把「已经到位」当成失败 | v0.17.2：同阶段静默返回 |

第 3 条顺带留下一条经验：**工具返回里的错误，模型不一定读**。凡是「状态没改成」的情况，都该用显式失败形态，而不是混在正常内容里。

## 四、没验到的东西（如实列出）

A1–A12 里 11 条需要真实条件才能验，本轮一条都没验：

| 需要什么 | 才能验的条目 |
|---|---|
| 4 台真实摄像头 + PoE 交换机 | A1 拉流、A2 流状态、A10 厂商云关闭 |
| 目标 Linux 宿主机（`/mnt/nvr` 挂载、fstab、NTP） | A5 24h 缺口、A6 7 天淘汰、A8 断电自启、A11 拔盘 |
| 手机 + 蜂窝网络 + 现场秒表 | A3 首帧、A4 延迟 |
| 外网环境 | A9 端口不可达 |

还有三项已知未修、已归属 T3/T5：`t1-selfcheck.sh` 把 0.0.0.0 监听降级为 SKIP（对 A9 无把关力）、`retain.days` 没有门禁、`alerts/detections.retain` 默认 10 天与环境 7 天预算冲突。

## 五、三条可复用的结论

1. **「自检通过」不等于「验收通过」。** 交付方跑绿自己的 17 项，只证明它的脚本自洽；审查方必须拿**另一套判据**（这里是 A1–A12 的判定方式）去核。这一轮 4 个阻塞项里有 2 个是 P0，全都藏在那 17 项全绿的身后。
2. **门禁要能被反证。** 只写「检查配置合法」的门禁，最可能的结果是永远全绿。让门禁自己去吃坏数据、必须变红，才算数。
3. **阶段属于项目，会话只是执行者。** 这不是洁癖：接单、实现、审查各用一个会话是常态，绑在会话上就必然出现「同一个项目三个进度」。

复跑命令（在项目目录）：

```bash
bash scripts/validate.sh            # 28 项静态门禁
bash scripts/render-config.sh --stdout   # 渲染预检（需 .env 或 --env-file）
docker compose config -q            # compose 语法
python scripts/check-rendered-config.py  # Frigate schema 语义门禁
```

面板（看这轮跑过什么）：DSH 里打开插件详情页，或 `curl 'http://<DSH>/capability-router/panel'`。
